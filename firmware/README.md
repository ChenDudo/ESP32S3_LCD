# ESP32-S3N16R8 + 正点原子 ATK-MD0350 3.5 英寸电容屏示例

这个示例面向 **正点原子 ATK-MD0350 3.5 英寸 480×320 电容触摸屏模块（V2.4）**，
开发板按 **ESP32-S3-WROOM-1-N16R8（16 MB Flash + 8 MB OPI PSRAM）** 配置。
上电后显示三块数据卡（温度 / 湿度 / 气压）和 GNSS 定位信息；手指触摸会在触摸位置画点并在底部显示坐标。

> 显示是 **16 位 8080 并口**，触摸是 **I²C**。
> 网上「3.5 寸屏用 SPI / XPT2046」的接线方式在这块屏上完全不适用。

## 1. 接线

默认接线都在 [`include/board_pins.h`](include/board_pins.h) 中，与 `硬件设计/引脚分配表-电容版.csv` 一致。
核心板必须引出下列 GPIO；如果你的核心板引脚编号不同，只改这个文件即可。

| 排针脚号 | 屏模块丝印 | 实际功能               | ESP32-S3 GPIO | 说明                            |
| -------: | :--------- | :--------------------- | ------------: | :------------------------------ |
|        1 | CS         | LCD 片选               |            18 | 10K 上拉                        |
|        2 | RS         | 命令/数据选择          |            21 |                                 |
|        3 | WR         | 写使能                 |            17 | **走线最短**              |
|        4 | RD         | 读使能                 |            39 | 10K 上拉到 3.3 V，只写模式      |
|        5 | RST        | LCD 复位               |            38 |                                 |
|   6 ~ 21 | DB0~DB15   | 16 位数据              |        1 ~ 16 | 一根不能少                      |
|       22 | GND        | 地                     |           GND |                                 |
|       23 | BL         | 背光，高=亮            |            40 | 地板 10K 下拉                   |
|   24, 25 | VCC3.3     | 主电源                 |         3.3 V | **不要接 5 V**            |
|   26, 27 | GND        | 地                     |           GND | 必须共地                        |
|       28 | VCC5       | 背光 5 V（备用）       |           5 V | 模块 R14 未焊，接上不通电       |
|       29 | MISO       | **NC**           |            — | 电容版未连接                    |
|       30 | MOSI       | **I²C SDA**     |            42 | 模块内已有 4.7K 上拉            |
|       31 | PEN        | **触摸中断 INT** |            46 | **10K 上拉（决定 I²C 地址 0x14）** |
|       32 | BUSY       | **NC**           |            — | 电容版未连接                    |
|       33 | CS         | **触摸复位 RST** | 48（底板）/ 47（开发板） | **不是片选！** 详见下方说明 |
|       34 | CLK        | **I²C SCL**     |            41 | 模块内已有 4.7K 上拉            |

注意：

- 排针的**丝印名沿用了电阻屏时代的命名**。33 脚写着 CS，实际是触摸复位；照丝印接成片选的话触摸不会工作。
- 不要把 GPIO 19/20 用于屏幕，它们用于原生 USB。
- N16R8 的 GPIO 26~37 通常连接板载 Flash/PSRAM，不要在核心板上另接外设。
- `GPIO 46` 是**输入专用脚**，只能读、不能推，所以触摸 INT 只能靠上拉（开发板上用内部约 45k，正式底板务必焊 10K 到 3.3 V）。GT1151Q 靠复位释放瞬间 INT 的电平选 I²C 地址：**上拉 → 0x14**，拉低 → 0x5D。
- **33 脚（触摸复位）在开发板上的接法不同**：核心板把 `GPIO48` 经 0Ω 直接接给了板载 RGB WS2812（网络名 `GPIO48 RGB_CTRL`），拿它做复位会让灯乱闪、个别板子电平还被带偏；`GPIO47` 引在 **J2 第 16 脚**，是空闲的。所以 `board_pins.h` 里用 `BOARD_TP_RST_ON_IO47` 切换：

  ```cpp
  #define BOARD_TP_RST_ON_IO47 1   // 开发板：TP_RST=IO47，GPS_PPS 不可用
                                   // 自制底板改成 0：TP_RST=IO48，GPS_PPS=IO47
  ```
- **核心板板载 WS2812 会在启动时被熄灭**（`include/rgb_led.h` 的 `rgbLedOff()`，发一帧全 0 数据）。
  WS2812 是锁存器件，单纯把 IO48 拉低不会清掉已点亮的颜色，所以必须发数据帧。想让它亮起来就调用
  `neopixelWrite(48, r, g, b)`；自制底板上 IO48 是触摸复位，`rgbLedOff()` 会自动跳过。
- 杜邦线要短。20 MHz 已经很快，接线超过 15 cm 建议先把 `freq_write` 降到 10 MHz。

## 2. 安装和编译

推荐使用 VS Code 的 PlatformIO 扩展：

1. 安装 VS Code。
2. 在扩展市场安装 **PlatformIO IDE**。
3. 用 VS Code 打开 `firmware` 目录（不是仓库根目录）。
4. 插件自动读取 `platformio.ini`，下载 ESP32 平台和 LovyanGFX。
5. 点底部 `✓` 编译，或运行：

   ```powershell
   pio run
   ```

工程已经为 N16R8 设置：

```ini
board_upload.flash_size = 16MB
board_build.flash_mode = qio
board_build.arduino.memory_type = qio_opi
board_build.partitions = default_16MB.csv
```

## 3. 烧录

1. 用能传数据的 USB 线连接核心板。
2. 优先使用板上的 **USB-UART** 口；只有原生 USB 口也可以直接烧。
3. 烧录：

   ```powershell
   pio run --target upload --upload-port COMx
   ```
4. 完成后按一下 `RST`，看串口：

   ```powershell
   pio device monitor --port COMx --baud 115200
   ```

识别不到设备时，按住 `BOOT` → 点 `RST` → 松开 `BOOT`，再烧一次。

## 4. 第一次不亮时按这个顺序查

1. **背光**：把 BL 直接短到 3.3 V，应看到白屏或花屏。全黑说明供电或排母接触有问题，先把这步排除。
2. **供电**：万用表量屏 24/25 脚 = 3.3 V，且 22/26/27 脚与 GND 导通。
3. **降频**：`freq_write` 改 10 MHz，杜邦线缩短。
4. **颜色红蓝颠倒**：`cfg.rgb_order = true`。
5. **画面方向不对**：调 `lcd.setRotation(0~3)`。
6. **花屏、错位**：优先怀疑 D0~D15 顺序错位，用逐位取反的单色测试定位。
7. **触摸没反应**：
   - 串口看有没有 `GT1151Q ready at 0x14, product id "1158"`；
   - 显示 `NOT FOUND` 时先量 33 脚（触摸复位）复位后是否为高；
   - 再量 31 脚（INT）静态是否为高——**INT 必须上拉**，实测这块屏的芯片靠它选地址，
     悬空会让芯片进入不应答状态（详见第 8 节）。

## 5. 屏驱动 IC 不确定时

旧版手册写的是 **NT35310**，新资料写 NT35310 或 ST7796。两者引脚完全一样，但初始化序列不同：

- 默认代码用 `lgfx::Panel_ST7796`。
- 不行就把 `main.cpp` 顶部的 `using PanelType = lgfx::Panel_ST7796;`
  换成 `lgfx::Panel_ILI9488` 再试。
- LovyanGFX 没有 `Panel_NT35310`；两者都不行时需要按 NT35310 的初始化表写一个自定义 Panel 类。
- 底板上 `LCD_RD` 接了 GPIO39 并留了上拉，需要读 ID 时把 `cfg.readable = true`、`cfg.pin_rd = 39` 即可。

## 6. 扩展外设：AHT20 / GY-BMP280 / ATGM336H

三个外设**不占新 GPIO**：两个传感器挂在触摸的 I²C 上，GPS 用原 J3 调试口的 UART。
驱动都写在 `src/sensors.cpp` 里，**不引第三方库**。

| 外设 | 型号 | 接口 | 地址 / 波特率 | 接线 |
| :--- | :--- | :--- | :--- | :--- |
| 温湿度 | AHT20 | I²C | 0x38 | J4-2 SDA → IO42，J4-3 SCL → IO41 |
| 气压 | GY-BMP280 | I²C | 0x76 | 与 AHT20 并联同一组 SDA/SCL |
| GNSS | ATGM336H-5N31 | UART | 9600 8N1 | 模块 TXD → IO44，RXD → IO43，PPS → IO47（可选） |

J4 排针顺序：**3V3 / SDA / SCL / GND**。

注意：

- 三个 I²C 器件地址不冲突（触摸 0x14、AHT20 0x38、BMP280 0x76）。三块板载上拉并联后约 1.6K，正常可用。
- GPS 占用 UART0 的两个引脚（43/44）后，**硬件串口日志就没有了**，控制台走 USB-CDC，烧录也走 USB。
- AHT20 必须远离背光和 DC-DC，并开透气孔，否则温度读数会高 3~8℃。
- 室内基本定不到位，测 GPS 要拿到窗边或室外，冷启动等 30~40 秒。
- 屏幕界面用的是 LovyanGFX 内置 ASCII 字体（TEMP / HUMI / PRES / GNSS），要显示中文需引入 `fonts::efontCN_16`，会明显增加固件体积。

## 8. 触摸驱动：为什么没直接用 `lgfx::Touch_GT911`

实测这块屏的触摸 IC 是 **GT1151Q**（`0x8140` 返回产品 ID `"1158"`），和 GT911 有三处硬性差异，
任何一处都会导致“驱动初始化成功但读不到/读错坐标”。所以 `include/touch_gt1151.h` 里自己实现了
一个 `lgfx::ITouch` 子类，`lcd_panel.h` 里用它替换了 `Touch_GT911`。

**差异一：触点寄存器布局不同。**（`GT1151Q编程指南.pdf` 3.3 节）

| 地址 | GT1151Q | GT911 驱动的假设 |
|---|---|---|
| 0x8150 | point1 x 低字节 | track_id |
| 0x8151 | point1 x 高字节 | x 低字节 |
| 0x8152 | point1 y 低字节 | x 高字节 |
| 0x8153 | point1 y 高字节 | y 低字节 |

GT911 驱动会整体错开一个字节，坐标算出来是乱的。

**差异二：INT 的作用不同。** GT911 驱动只在 `gpio_in(pin_int) == 0` 时才去读寄存器；
本屏 INT 接在 IO46（ESP32-S3 的**输入专用脚**，无法输出），开发板上也没焊外部上拉，
INT 恒为高，驱动一次寄存器都不读。现在的实现是**纯轮询**，INT 只承担两件事：
上电时给芯片选 I²C 地址（上拉→`0x14`，拉低→`0x5D`）、给芯片一个确定的高电平。

**差异三：状态位必须无条件清。** `0x814E` 的 bit7 置位后，主机读完必须写 0，
否则芯片认为主机没读完，不再产生新的上报——表现就是“按第一次有反应，之后彻底死掉”。

**初始化顺序（不能颠倒）：**

```
pinMode(TP_INT, INPUT_PULLUP)     // 先让 INT 为高，决定地址 = 0x14
RST 低 15ms → 高 → 等 120ms        // 手册 4.2 节复位时序 + 自校准
探测 0x14，读 0x8140 校验 4 个可打印 ASCII；失败再试 0x5D
```

底板设计里 R9（10K 上拉到 3V3）就是为这一步准备的；开发板阶段靠 IO46 的
内部上拉（约 45k）也能工作，但**正式底板务必焊外部 10K**。

坐标旋转不用自己做：`getTouchRaw()` 返回面板原始竖屏坐标（320×480），
`Panel_Device::convertRawXY()` 会按 `setRotation()` 自动换算成屏幕坐标（480×320）。

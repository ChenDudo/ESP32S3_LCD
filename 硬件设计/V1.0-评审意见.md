## 二、必须改（1 项，影响功能）

### R36：TP_INT 接成了下拉，必须改成上拉

```
现状：RT_PEN ── 10k ── GND     ❌
应为：RT_PEN ── 10k ── 3V3     ✅
```

**为什么必须改**：GT1151Q 数据手册 1 节明确要求「INT 口必须上拉」，且芯片在复位释放瞬间靠 INT 电平选 I²C 地址。

实测过一次同类故障：INT 没有上拉（悬空）时，芯片会进入不应答状态——`0x814E` 恒为 `0x00`、读产品 ID 返回 `0xFF`、触摸完全无反应。加回上拉后立刻恢复，地址为 `0x14`。

固件虽然会依次探测 `0x14` / `0x5D`，但芯片在 INT 被**硬拉低**时是否会稳定工作在 `0x5D` 未经验证，不能赌。

**改法**（任选其一）：

1. 直接把 R36 下端从 GND 改接 3V3（推荐，与其他上拉一致）；
2. 改成 3P 跳线：1=3V3、2=RT_PEN、3=GND，默认短接 1-2，保留手动切地址的能力。

## 三、必须注意（2 项，不改会埋雷）

### 1. H4 引出了 IO35 / IO36 / IO37

这三个脚在 **N16R8** 模组上被 **Octal PSRAM 占用**（PSRAM 的 SPIIO4~7 / DQS）。一旦外接任何负载，PSRAM 读写就会失败，表现是随机死机、重启或 `alloc` 失败。

改法：
- 从 H4 上删掉这三脚（推荐），或
- 保留但丝印明确标注 **`IO35~37 = PSRAM 专用，禁止外接`**。

### 2. H3 与触摸复位共用 IO47

```
H3 闭合：IO47 ── CN3-5（GPS PPS）
而 IO47 同时是 TP_RST
```

单独看都合理，但同时用就冲突。**默认不装 H3**，并在丝印/文档写明「H3 不装；PPS 不可用」。

若确实想要 PPS，需要把 TP_RST 挪到别的脚——但 IO48 在核心板上接 RGB 灯、IO45 是 strapping 脚、IO19/20 是 USB，实际没有更好的选择。建议就放弃 PPS。

## 五、可优化（不影响功能）

- **31 颗 0Ω 串联电阻**：功能上没问题，优点是方便改线，代价是焊接量和面积。若确定不再改线，可把部分合并直连；留着也不亏。
- **CN3 丝印**：3/4 脚现在叫 `ERX` / `ETX`，是从 MCU 视角命名的，用户手里的 GPS 模块丝印是 `TXD`/`RXD`，容易接反。建议丝印直接写 `GPS-TXD→` / `GPS-RXD←`。
- **4 个 I²C 座并联**：够用但偏多，两个就够；四个都插满时总线电容上升，固件保持 100kHz 即可。
- **U1/U2 用两个 1×22 单排座**：能用，但机械强度不如 2×22 双排座；确认两排孔距与核心板一致（22.86mm）。

## 仍需改（3 项）

### 1. R36 + R40 组成了分压，RT_PEN 被钉在 1.65V

```
现状：3V3 ── R40 10k ──┬── R36 10k ── GND
                       └── RT_PEN      → 静态 1.65V
```

1.65V 落在 TTL 的**未定义区**（>2.31V 才算高、<0.99V 才算低），芯片复位时采样 INT 选地址会得到不确定结果；也违反手册「INT 必须上拉」。

**改法：删掉 R36（或空焊），只保留 R40 上拉到 3V3。** RT_PEN 就会稳定在 3.3V，地址固定 `0x14`。

### 2. C10 只有焊盘，原理图上找不到符号

- BOM 里有 C10（47µF）
- 顶层图里 C10 的封装在板子中部（D6.3 电解电容位置）
- 但原理图第 1 页只有 C1~C9、C11、C12 共 11 个电容，**没有 C10**

说明 C10 的符号漏画或未连线，焊盘大概率是悬空的（`No Net`）。请在 EDA 里点一下 C10 的两个焊盘确认网络：如果都是 No Net，要么补符号（建议接到 3V3 与 EGND，正好补上缺的储能电容），要么从 BOM 和 PCB 删除。

### 3. 3V3 轨仍然没有储能电容

现在 3V3 上只有 C1、C2、C5~C8 共 6 颗 100nF（合计 600nF）。屏的背光是 82mA 阶跃，开机瞬间会拉塌 3V3。

**建议：把 C10 改成接 3V3/EGND 的 22~47µF，靠近 H1 的 24/25 脚。** 正好一举两得（问题 2 也解决了）。

## 新发现的机械问题

按顶层装配图量：板框约 **59 × 98.5mm**，而屏模块是 **56.4 × 97.4mm**——两者几乎一样大。

- H1（34P）在板子顶边，U1/U2（核心板排母）在板子中上部，**两者画在同一面**；
- 屏插进 H1 后，模块本体正好覆盖整块板，会**压住核心板**；
- 板上**看不到安装孔**（丝印图里没有圆孔）。

需要确认：核心板到底插在正面还是背面？如果 U1/U2 和 H1 同面，建议把 U1/U2 移到背面；另外至少要加 2~4 个 M2 安装孔，否则装不进外壳、也没法固定。

## 仍然没做（可选）

# 第四轮复审（2026-11-06 21:30 更新版，对照 20:46 版原理图）

## 一、TVS：单向还是双向？—— 结论：保持单向，不要换双向

BOM 现状：D1 = **SMAJ5.0AJ**（WeEn 瑞能，LCSC C7464035，SMA 封装，400W）。原理图符号是带折角阴极横杠的**单向** TVS，阴极接 E5V0、阳极接 EGND，方向正确 ✅。

| 对比项 | 单向 SMAJ5.0A / 6.0A（推荐） | 双向 SMAJ5.0CA |
|---|---|---|
| 正常偏置 | 只能单极性 0~+V_RWM | 正负皆可 |
| 正向浪涌 | 雪崩击穿，钳位 +V_C ≈ 9.2V（5.0A 档） | +V_C ≈ 9.2V |
| 负向 ESD / 浪涌 | 体二极管正向导通，钳位 **≈ −0.7~−1V** | 雪崩击穿，钳位 **≈ −9.2V** |
| 装反风险 | 有（相当于二极管把 5V 短路到地，F1 会切断） | 无 |
| 适用场景 | DC 电源轨、0~3.3V 单极性信号 | 交流、会摆到负压的线（RS-485 / CAN / 音频） |

**理由**：

1. 这块板的 5V 是纯直流单极性电源轨（Type-C 只取 5V，CC 用 5.1k 下拉，无 PD 协商），正是单向管的目标场景；双向管是为会跨过 0V 摆动的线路设计的，在这里没有任何收益。
2. **常见误解**：「单向」指的是正常工作电压的方向，不是「只能防一种极性的干扰」。单向 TVS 同样能吸收正负两种极性的 ESD——正向走雪崩、负向走体二极管正向导通。而且负向尖峰被钳在 ≈ −1V，比双向管的 −9.2V **保护得更好**。
3. 单向管万一贴反（横杠接了地）会正向导通把 5V 短路，但前面有 F1（1206L110THYR，1.1A PTC）限流断开，不会烧线材和充电头；双向管「不挑方向」这个唯一优势，在这里抵不上它的高负向钳位。
4. 板上其它要加 ESD 保护的单极性信号（I²C、GPS UART、复位）同理优先单向。

## 二、真正建议改的不是「单向/双向」，而是 V_RWM 档位

Type-C 默认 5V 档（vSafe5V）允许 **4.75~5.5V**，很多充电头空载就是 5.2~5.3V。而 SMAJ5.0A 的 V_RWM 只有 **5.0V**，等于长期工作在额定关断电压之上：

- 5.0V 档 datasheet 的反向漏电流上限本来就比 6V 以上档**高几个数量级**（数百 µA 对 ~1µA）；
- 电压再抬高、温度再上升，漏电会继续增大 → 发热 → 漏电更大，存在「临界偏置」隐患，也可能给 F1 增加无谓负担。

**建议把 D1 换成 SMAJ6.0A**（V_RWM 6.0V、V_BR 6.7~7.4V、V_C ≈ 10.3V）或 **SMAJ6.5A**（V_C ≈ 11.2V）：

- 仍是**单向**、仍是 SMA 封装（SMA_L4.5-W2.7-LS5.1-RD），原理图和 PCB **都不用动，只改 BOM 型号**；
- 代价是钳位电压高约 1V，但 5V 轨后级是 LDO + 10µF/47µF 储能，完全可接受；
- 买料认准 **A = 单向，CA = 双向**（SMAJ6.0CA 才是双向）。BOM 里 SMAJ5.0AJ 结尾的 J 是厂家料号后缀，不代表双向，以原理图的单向符号为准。

如果坚持不换料：实测充电头空载 VBUS ≤ 5.1V，并在满载通电 30 分钟后确认 D1 不发热，可以继续用；但量产或会换充电头的场合不建议。

布局保持现状：VBUS → F1 → E5V0，D1 挂在保险丝之后 ✅，这样 TVS 自身击穿短路时 F1 能切断。D1 到 EGND 的回路继续走短粗线。

# 附：背光调光能力确认（2026-11-06）

**结论：V1.0 底板硬件原生支持 PWM 调光，不需要改板、不需要加元件；当前固件只做了开/关，要实现无级调亮度只需改代码。**

## 链路

```
ESP32-S3 IO40 ──(底板 R23 0Ω)── H1-23 BL_CTR
                                │
                    底板 R35 10k 下拉到 GND（复位时背光默认灭）
                                │
                    模块 R21 1K ── Q1 S8050 基极
                    发射极 → GND，集电极 ← LEDK1~LEDK6
                    每路串 10Ω（R15/R16/R18/R20/R22/R23）
                    LEDA ← R13 0Ω ← VCC3.3（模块默认）
```

依据：`ATK-MD0350 V2.4.pdf` 第 1 页背光电路。BL_CTR 是纯逻辑/PWM 输入，模块内部**没有恒流驱动芯片、没有 EN/滤波电容**，就是一个 NPN 开关，所以占空比直接等于平均亮度。

## 硬件侧要点

- IO40 是普通输出脚，ESP32-S3 的 LEDC 可通过 GPIO 矩阵映射到任意输出脚，无引脚冲突；LovyanGFX 配置里也没有占用 LEDC。
- 底板 R35 10k 下拉是加分项：MCU 复位/高阻时 BL_CTR 被钉低，背光不会自己亮，也不会闪白屏。
- **亮度上限固定**：LEDA 由 3.3V 经 R13 0Ω 供电，6 路 10Ω 限流是按 3.3V 配的，PWM 只能往下调，不能比「全亮」更亮。
- 模块丝印提示「觉得不够亮可焊 R14」——R14 是 0Ω 改接 VCC5。**换 5V 前必须先拆掉 R13**，否则 3.3V 与 5V 被两个 0Ω 直接短接；而且 10Ω 限流在 5V 下电流会翻几倍，LED 和 Q1 都可能过载。不建议为了亮度去动它，PWM 调光够用。
- 调暗会降低 3V3 轨的平均电流，对前面提到的核心板 LDO 温升是好事。

## 固件侧现状

`board_pins.h` 定义 `LCD_BL = 40`；`main.cpp:174-179` 与 `display_test.cpp:229-236` 都只有 `digitalWrite(HIGH/LOW)`，**没有任何 LEDC / PWM 代码**，也没有亮度变量或滑动手势。

## 建议参数（Arduino-ESP32 2.x，platformio 用 espressif32@6.12.0）

| 参数 | 取值 | 理由 |
|---|---|---|
| 频率 | **8 kHz**（1 kHz → 20 kHz → 8 kHz 实测定稿） | 1kHz 有频闪重影 / 滚动条纹；20kHz 下 S8050 跟不上窄脉冲、低亮度几乎全黑；8kHz 每帧约 133 周期，两边兼顾 |
| 分辨率 | **8 bit**（8kHz 下 LSB ≈ 0.49µs） | 10 bit 的 LSB 约 0.12µs，远短于三极管存储时间，低端会完全非线性 |
| 最低占空比 | **≈5.5%（14/255，约 6.9µs 高电平）** | 高电平短于 3µs 时 S8050 导通不足，实测最低档几乎全黑 |
| 亮度映射 | `duty = (level/100)^2.2 × 241 + 14` | gamma 校正，否则低段变化太跳 |

注意：严谨拍屏 / 高速录像把亮度调回 100% 直亮。**20kHz 已实测否决，不要再往上提**；
若低亮度仍偏暗，把 `kBlFreq` 降到 `4000`（LSB 0.98µs）即可，其余参数不用动。

**重影问题复核（2026-11-06 22:05）**：实测反馈「亮度显示有重影」，定位到两个独立来源，均已修复：

1. **文字残影（主要现象）**——LovyanGFX 的 `setTextColor(color)` 单参数会把
   `fore_rgb888` 与 `back_rgb888` 设成同色，字体渲染据此判定 `fillbg = false`
   （透明背景，只画字形像素）。连续调亮度时 `"BL 100%" → "BL   9%"` 的前导空格
   不绘制任何像素，旧数字笔画就留在原处，叠几次即成重影；原先那层 1px 黑色
   偏移描边还会再叠一层。现改为每次先按真实底色 `fillRect` 擦净，再用双参数
   `setTextColor(fg, bg)` 不透明绘制，并去掉偏移描边。新增 `screenBg/screenFg`
   跟踪当前底色：颜色页按明暗自动选黑 / 白字，FPS 模式用该帧动态深蓝底 + 绿字。
2. **画面频闪重影**——1kHz PWM 与 60Hz 刷新不同步（1000/60 非整数）+ 眼动
   phantom array。频率一度提到 20kHz，见下方回归记录。

**低亮度回归修复（2026-11-06 22:20）**：实测「最低亮度完全看不清」，
定位为上一轮 20kHz 的回归。根因不是占空比太小，而是 **S8050 跟不上**：

**绝对高电平时间**，不能只盯着频率。
